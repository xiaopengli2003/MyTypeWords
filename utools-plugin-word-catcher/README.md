# 词捕 · TypeWords 生词本

版本 **1.0.0**。划词或输入英文词句，由 AI 生成词条，检查保存后导出到 [TypeWords](https://typewords.cc/words) 自定义词典。

## 安装与首次使用

1. 在 uTools 开发者工具中创建项目，选择发布目录里的 `plugin.json`。开发时也可直接选择源码目录的同名文件。
2. 使用「词捕」「记单词」或「记生词」进入插件，在 **设置 → AI 服务** 填写 API 基础地址、Key 和模型 ID。
3. 点击刷新图标获取模型列表，也可手动填写；「测试当前配置」使用当前表单，无需先保存。完成后点「保存设置」。
4. 数据目录已有默认值，**无需先手动创建文件夹**。首次保存设置会创建目录、当天 JSON 和默认提示词。

默认位置为系统“文档”目录下的 `MyTypeWords/typewords-data`，兼容重定向的文档目录。需要其他位置时，进入 **设置 → 数据与导出 → 选择目录 → 保存设置**。保存前仍使用原目录；更换目录不会搬迁旧文件。详细规则见 [数据存储与迁移](docs/data-storage.md)。

## 记录与管理单词

- 普通指令进入词库；通过 uTools 划词功能选中英文进入时，文本预填到“导入词”。
- 单词或短语直接生成。输入句子时，点击目标词或手动填写；原句经 AI 清洗后成为第一条例句。
- 生成结果可编辑单词、音标、释义、例句，或展开完整 JSON。目标词输入框按 Enter 生成；输入区按 `⌘ / Ctrl + Enter` 生成，编辑器中同一快捷键保存。
- 词库按创建日期分组：当天默认展开，历史默认折叠。搜索覆盖全部日期的单词和中文释义，匹配分组自动展开。
- 更新已有词保留原创建日期。编辑时改成其他已有单词会拒绝覆盖；历史导出文件不随旧词编辑或删除而改写。
- “数据与导出”里点击「查看文件」，找到 `daily/YYYY-MM-DD.json`，在 TypeWords 的自定义词典页面导入。

文本清洗处理引号、所有格、连字、PDF 断行和多余空白；程序保留缩写大小写，AI 判断词形并生成英美音标、释义、例句、搭配、近义词、派生词和简要词源。保存前仍可人工修订。

## AI 服务设置

支持多套 OpenAI 兼容服务配置。下拉框选择要编辑的配置；「设为当前使用」并保存后切换生成服务。新增、模型下拉和刷新使用图标，附带悬停提示和可访问名称。

API 地址填写基础地址，例如 `https://example.com/v1`。粘贴带 `/models` 或 `/chat/completions` 的地址会移除末尾接口路径。本机服务可以使用 `http://127.0.0.1:11434/v1`，Key 可留空；远程服务需要 Key。接口不支持列出模型时，手填模型 ID 即可。

思考模式默认关闭。其他选项仅在服务商支持对应字段时使用，可能增加等待时间。模型列表与连接测试状态按配置分别保存，切换配置或修改连接信息后不会误用旧请求结果。

设置分类和主页面切换保留未保存草稿。底部操作栏仅在有修改或保存错误时出现；保存或撤销后隐藏。保存允许分步填写，生成时才检查服务是否完整。

## 数据、备份与恢复

词条主数据在 uTools 本地库中；数据目录保存服务配置、每日导出和提示词。`config.json` 含明文 API Key，词库备份不含 Key。

| 操作         | 结果                                                       |
| ------------ | ---------------------------------------------------------- |
| 导出词库     | 保存全部词条、采集原文、日期、每日存档和提示词             |
| 合并词库     | 合并备份，同名词及已有提示词保留本机版本，当天文件重新生成 |
| 导出配置     | 导出已保存的 AI 服务设置，包含明文 Key                     |
| 替换配置     | 替换服务设置并立即生效，保留本机数据目录                   |
| 恢复历史词条 | 把仅在历史每日文件中的词按原日期恢复，不覆盖同名记录       |

恢复前校验整个备份；写入失败会尝试回退，回退失败时明确报告。删除历史词后不会因为重启而自动恢复，只有明确使用恢复入口才会重新加入。

提示词在 `prompts/system-prompt.md`。点击「查看文件」定位后编辑，下次生成使用修改后的内容；文件不存在或内容短于有效提示词阈值（101 个字符）时使用内置默认。

## 窗口与兼容性

界面默认内容高度为 620，可随窗口宽高调整。正式预览以 800×620 为默认尺寸，也可检查较小窗口。普通进入不把指令名称填入输入框。

主窗口右侧 × 退出插件并收起 uTools。主窗口报告隐藏时也尝试退出；原生文件对话框和分离窗口受到保护。宿主的隐藏事件与系统缩放仍需实机验收。

运行文件只使用 CommonJS、Node 原生模块及标准 Web 技术，没有安装期依赖。Node 20.19.1 回归通过；Windows 路径与宿主分支有模拟测试，尚不代表完整 Windows uTools 实机验收。见 [兼容性说明](docs/compatibility.md)。

朗读仅完成 [方案调研](docs/speech-research.md)，v1.0.0 没有朗读按钮。

## 开发与发布

需要 Node.js 20 或更新版本。格式化工具仅用于开发，不会进入发布目录。

```sh
npm ci
npm run verify
npm run preview
npm run build
```

- `verify`：检查统一格式、JavaScript 语法、版本一致性、Logo 尺寸，以及六组回归测试。
- `preview`：启动仅限本机的隔离演示，不访问真实服务或词库。
- `build`：生成 `dist/word-catcher-v1.0.0/`，在 uTools 开发者工具中选择其中的 `plugin.json` 后打包。

```text
app.js              页面状态、渲染和用户操作
preload.js          uTools 桥接、网络请求及持久化
lib/core.js         文本清洗、词条规范和每日文件工具
lib/library.js      备份校验、恢复计划和原子写入
style.css           正式主题与响应式布局
test/               隔离回归测试
scripts/            开发、验证与构建命令
design/             使用生产样式的演示预览
docs/               数据存储、兼容性和朗读调研
assets/source/      高清 Logo 原稿与生成记录
```

使用两空格缩进、单引号、无分号，统一由 Prettier 执行。注释说明状态边界、数据来源和失败处理，不重复描述直观语句。新行为需要对应回归；修改运行文件清单时同步更新构建脚本。

开发用试用词脚本要求显式指定目录，不默认写入个人词库：`node scripts/add-trial-words.js /path/to/test-data [YYYY-MM-DD]`。六组测试使用系统临时目录、模拟宿主和本机 HTTP 服务，不读取个人配置，也不调用真实 AI。

正式 Logo 为 256×256 PNG；高清原稿保留在 `assets/source/logo-blue-source.png`。版本变更见 [CHANGELOG](CHANGELOG.md)。
